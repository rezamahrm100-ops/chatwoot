# Chatwoot CE — استقرار مستقل روی VPS مشترک

وضعیت: **بستهٔ آمادهٔ استقرار، نه تأیید نصب روی سرور**. این بسته از تصویر رسمی `chatwoot/chatwoot:v4.19.1-ce` استفاده می‌کند و هیچ تغییری در سورس Chatwoot نمی‌دهد.

## زیرساخت بررسی‌شده
گزارش read-only اجرای Newsroom VPS audit در ۱۴ نوامبر ۲۰۲۶ (Run 43601181996): ۶ پردازنده، ۱۵GiB رم کل، ۱۴GiB رم قابل استفاده و ۵۶GB دیسک آزاد. `http://127.0.0.1:1111/` برای Blinko پاسخ 200 داشته است. رانر Newsroom به Docker دسترسی ندارد؛ **این رانر را صاحب دسترسی Docker نکنید.** استقرار عملیاتی Newsroom نیز هنوز تأیید نشده است.

## حفاظت از پروژه‌های دیگر
- پروژه Compose فقط `chatwoot_ce` است؛ PostgreSQL 16، Redis 7.4، Rails و Sidekiq خودش را دارد.
- تنها پورت میزبان `127.0.0.1:3001` است؛ پایگاه داده و Redis هیچ پورت عمومی ندارند.
- داده‌ها در `chatwoot_ce_postgres`، `chatwoot_ce_redis` و `chatwoot_ce_storage` باقی می‌مانند؛ Blinko (`personal_memory`) و Newsroom بدون تغییر می‌مانند.
- `docker compose down -v`، پاک‌سازی volume و نصب مجدد سیستم‌عامل در این بسته وجود ندارد.
- برای انتشار عمومی، TLS و دامنهٔ واقعی لازم است؛ بدون آن، نصب فقط در تونل SSH قابل استفاده است.

## پیش‌نیازهای دستی و مرز اختیارات
1. یک **مخزن خصوصی مخصوص استقرار** ایجاد شود؛ کدهای اجرایی این بسته را در مخزن عمومی Chatwoot با رانر شخصیِ دارای دسترسی به میزبان اجرا نکنید. WICC فقط CI ایستای بدون اسرار را اجرا کند.
2. مدیر VPS یک حساب و رانر Linux اختصاصی `chatwoot-ce-deploy` برای همین مخزن ثبت کند، `/opt/chatwoot-ce` را با مجوز مناسب برای آن آماده کند و دسترسی محدود Docker را فراهم کند. عضویت در گروه `docker` عملاً اختیار ریشه می‌دهد؛ اگر جداسازی سخت لازم است، Docker rootless اختصاصی به کار رود. از `newsroom-audit` یا رانر Blinko استفاده نشود.
3. پیش از دامنهٔ واقعی، نصب آزمایشی با URL داخلی `http://127.0.0.1:3001` انجام می‌شود. برای اپ اندروید و وب‌هوک تلگرام باید DNS، reverse proxy و HTTPS معتبر برقرار شود. این بسته به پورت 80/443 یا تنظیمات پروکسی موجود دست نمی‌زند.
4. پشتیبان‌گیری رمزنگاری‌شده خارج از VPS و آزمون بازیابی باید تنظیم شود؛ اسکریپت حاضر فقط بکاپ محلی می‌سازد.

## نصب خصوصی روی VPS، پس از اتصال رانر اختصاصی
بستهٔ تأییدشدهٔ Release را به یک پوشهٔ موقت جدا استخراج کنید. اجرای دستور زیر فقط با حساب استقرار اختصاصی و **پس از** بررسی دسترسی/ظرفیت مجاز است:

```bash
bash scripts/deploy.sh
```

برای نصب دستی فقط در همان پوشه، ابتدا `bash scripts/init-env.sh` و سپس `bash scripts/preflight.sh` را اجرا کنید. برای دسترسی از رایانهٔ محلی، تونل SSH روی پورت 3001 ایجاد کنید. اگر با اندروید به سرور نیاز دارید، ابتدا دامنهٔ HTTPS را راه‌اندازی کنید.

## اتصال عمومی پس از آماده‌شدن DNS و TLS
نمونهٔ تنظیم در پراکسی Caddy موجود، بدون تغییر در سرویس‌های قبلی:

```caddy
chatwoot.example.org {
    reverse_proxy 127.0.0.1:3001
}
```

این آدرس نمونه است و **نباید بدون جایگزینی با دامنهٔ واقعی استفاده شود**. پس از تنظیم TLS، متغیرهای `FRONTEND_URL=https://REAL_DOMAIN` و `FORCE_SSL=true` را در `.env` تغییر دهید و فقط Rails و Sidekiq خود Chatwoot را بازآفرینی کنید. برای تلگرام، از پنل Chatwoot یک Telegram inbox بسازید و توکن ربات خودتان را فقط در رابط امن وارد کنید.

## راهنمای مدیریت
- سلامت: `bash scripts/health.sh`
- بکاپ محلی: `bash scripts/backup.sh`
- مشاهدهٔ وضعیت: `docker compose -f compose.yaml ps`
- لاگ سرویس: `docker compose -f compose.yaml logs --tail 100 rails sidekiq`
- ورود اول: `/app/auth/signup`، پس از ساخت حساب مدیر `ENABLE_ACCOUNT_SIGNUP=false` شود.
- ایمیل و SMTP باید پیش از دعوت کاربر و ارسال اعلان ایمیلی پیکربندی شود؛ مقدار `noreply@example.invalid` در تنظیم اولیه واقعی نیست.
- قبل از هر به‌روزرسانی، Release و تغییرات پایگاه داده مرور و بکاپ گرفته شود. بازگرداندن image قدیمی لزوماً مهاجرت پایگاه داده را برنمی‌گرداند.
- هزینهٔ Community Edition برابر صفر است، ولی هزینهٔ VPS، فضای ذخیره‌سازی و سرویس‌های خارجی ممکن است وجود داشته باشد.

## وضعیت اجرای این بسته
فایل‌ها و کنترل‌ها در محیط آماده‌سازی بررسی می‌شوند. بدون هویت اجرایی اختصاصی VPS، تأیید فضای دیسک در زمان نصب، دامنه و TLS، ادعای «استقرار عملیاتی کامل» درست نیست.
